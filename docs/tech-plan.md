Статус: **на согласовании**. Реализацию начинаем после «ок» владельца.

## 1. Архитектура простыми словами

```
 Телефон / компьютер (браузер)
          │
          ▼
 ┌─────────────────────────────┐
 │  Next.js (сайт + сервер)    │  ← страницы, формы, проверка данных
 │  хостинг: Vercel (Hobby)    │
 └──────────────┬──────────────┘
                │ защищённое соединение
                ▼
 ┌─────────────────────────────┐
 │  Supabase                   │
 │  • Postgres — база данных   │  ← RLS: база сама проверяет, кому что можно
 │  • Auth — вход и пароли     │
 │  • Storage — файлы (v2)     │
 └─────────────────────────────┘
```

- **Отдельного «бэкенда» нет.** Next.js сам и показывает страницы, и обрабатывает формы
  (Server Components — чтение, Server Actions — изменения). Это меньше кода и меньше мест для ошибок.
- **Главная защита — в базе (RLS, Row Level Security).** Даже если в коде страницы ошибка,
  база не отдаст чужие данные: каждое правило «кто что может видеть и менять» записано прямо в Postgres.
- **Проверка ввода — Zod** (библиотека схем): длина текстов, допустимые значения, без лишних полей.
- **Шрифты — свои, без Google** (`@fontsource`), чтобы не передавать третьим лицам данные посетителей.

### Технологии

| Слой | Выбор | Почему |
|---|---|---|
| Интерфейс | Next.js 16 (App Router) + React 19 + TypeScript | современно, одна кодовая база для сайта и сервера |
| Стили | Tailwind CSS 4 + токены из дизайна | быстрые адаптивные экраны, единый стиль |
| База и вход | Supabase (Postgres + Auth) через `@supabase/ssr` | бесплатный тариф, готовая авторизация, RLS |
| Проверка данных | Zod | одинаковые правила на клиенте и сервере |
| Тесты | Playwright (e2e, телефон + компьютер), Vitest (мелкие функции) | проверка реальных сценариев |
| CI | GitHub Actions | автопроверка каждого изменения |
| Хостинг | Vercel Hobby | бесплатно; публикация — только с вашего согласия |

### Бесплатные тарифы и их ограничения (важно знать заранее)
- **Supabase Free:** до 2 проектов, база 500 МБ — для MVP с запасом. Проект «засыпает» после 7 дней без активности
  (будится одной кнопкой). Встроенная отправка писем (подтверждение email, сброс пароля) ограничена
  несколькими письмами в час — для тестов хватит; для реальных пользователей позже понадобится почтовый сервис
  (у многих есть бесплатный уровень, подключим только с вашего согласия).
- **Vercel Hobby:** бесплатно, но по правилам — для личных, некоммерческих проектов. Для теста MVP подходит;
  при запуске коммерции нужен будет платный тариф (решение — ваше).

### Мобильная версия — полноценная, а не уменьшенная
- **Внизу — панель вкладок:** «Мои круги», «Найти», «Уведомления», «Профиль». Большие зоны нажатия (≥ 44 px), учёт «чёлки» и нижней полосы iPhone.
- **Действия — нижние шторки** (меню круга, жалоба, выход) вместо мелких выпадающих меню; на компьютере те же действия — в диалогах.
- **Формы — по одному шагу на экран** (создание круга), правильные типы клавиатуры (`email`, `search`).
- Темы и фильтры — горизонтальная прокрутка; кнопка «Написать шаг» всегда под пальцем.
- Проверяем на ширине **320 px** (самые маленькие телефоны) — это уже в автотестах.

## 4. Модель данных

Обозначения: `PK` — уникальный ключ, `→` — ссылка на другую таблицу. Все таблицы — с включённым **RLS**.

### Пользователи
**profiles** — профиль (1 к 1 с аккаунтом Supabase Auth)
| Поле | Тип | Примечание |
|---|---|---|
| id | uuid PK → auth.users | |
| nickname | citext, уникальный | 3–20 символов: латиница, цифры, `_` |
| avatar_tone | enum | цвет буквы-аватара (фото — в v2) |
| about | text ≤ 300 | |
| city | text ≤ 60, необязательно | |
| interests, skills | text[] | до 10 тегов каждого вида |
| vis_avatar, vis_about, vis_city, vis_interests, vis_skills | enum `private / circles / public` | **по умолчанию `private`** |
| role | enum `user / moderator / admin` | |
| age_confirmed_at | timestamptz | галочка «мне есть 16» |
| created_at | timestamptz | |

Никнейм виден участникам ваших кругов и создателю круга, куда вы подали заявку. Email хранится только в Supabase Auth и **никогда** не попадает в публичные запросы.
`public` = «все вошедшие пользователи»; гостям без входа профили не показываются вообще.

### Круги
**circles**: id, owner_id → profiles, title (≤ 80), goal (≤ 200), description (≤ 1000), topic (enum), tags text[],
capacity (3–8), weeks (2–12), start_date, join_mode `open / approval`, listing `listed / unlisted` (по ссылке),
status `recruiting / active / finished / closed`, created_at.

**circle_members**: (circle_id, user_id) PK, role `owner / member`, joined_at.
При выходе запись удаляется, шаги остаются (автор показывается как «бывший участник»).
Если выходит создатель — роль переходит самому давнему участнику; если никого нет — круг закрывается.

**join_requests**: id, circle_id, user_id, message (≤ 300), status `pending / approved / rejected / withdrawn / expired`,
decided_by, decided_at, created_at. Одна активная заявка на человека и круг.

### Общение
**steps** (шаги недели): id, circle_id, author_id, week_no, body (≤ 2000), status `visible / under_review / removed`, created_at, edited_at.
**comments**: id, step_id, author_id, body (≤ 1000), status, created_at.
**reactions**: (step_id, user_id, kind) PK, kind `support / useful`.

### Безопасность
**blocks**: (blocker_id, blocked_id) PK, created_at.
**reports**: id, reporter_id, target_type `step / comment / user / circle`, target_id, reason (enum), details (≤ 500),
status `open / actioned / dismissed`, weight, created_at, resolved_by, resolved_at. Уникально: (reporter, target).
**moderation_actions** (журнал): id, moderator_id, action, target_type, target_id, reason, created_at.
**action_log** (для ограничения частоты): user_id, action, created_at.

### Уведомления
**notifications**: id, user_id, type, data (jsonb — только id объектов, без текста чужих сообщений), read_at, created_at.
**notification_settings**: user_id PK, prefs (jsonb: тип → в приложении / на почту), quiet_from, quiet_to, daily_digest, all_off.

### Ключевые правила доступа (RLS)
- Шаги, комментарии и список участников видят **только участники круга**.
- Писать шаги и комментарии могут только текущие участники; менять — только автор.
- Поля профиля отдаются через функцию, которая учитывает видимость поля, общие круги и блокировки.
- Заблокированные взаимно не видят профили и публикации друг друга и не могут вступить в круги друг друга.
- Заявки видят только их автор и создатель круга.
- Жалобы видит только автор жалобы (свои) и модераторы.

## 5. Защита от злоупотребления жалобами

Жалоба **никогда не удаляет контент автоматически**.

1. **Сразу после жалобы** публикация скрывается **только у того, кто пожаловался**. У остальных всё по-прежнему.
2. **Временное скрытие «на проверке»** (не удаление) для всех включается, только если:
   - пришло **3 жалобы от разных людей**,
   - их аккаунтам больше 7 дней, и это участники того же круга,
   - этих людей нет среди тех, чьи жалобы часто отклоняются.
   Автор видит пометку «на проверке» и продолжает видеть свою публикацию.
3. **Решение принимает модератор:** вернуть публикацию или удалить. Каждое решение пишется в журнал.
4. **Против «ковровых» жалоб:** не больше 10 жалоб в сутки на человека; на один объект — одна жалоба от одного человека.
   Если жалобы человека систематически отклоняются, их «вес» снижается и они перестают влиять на шаг 2
   (модератор их всё равно видит).
5. **Создателя круга нельзя «выжить» жалобами** — его контент уходит только в очередь модератора.
6. Автор жалобы остаётся анонимным для того, на кого пожаловались.

## 6. Одобрение новых участников

- У круга два режима вступления: **«Открытый»** (сразу, пока есть места) и **«По заявке»** (по умолчанию).
- Заявка: необязательное сообщение до 300 символов. Если в нём похоже на контакты, показываем предупреждение.
- Создатель видит: никнейм, сообщение, поля профиля с видимостью «Все» и сколько кругов человек довёл до конца.
  Закрытые поля создатель не видит — приватность не нарушается ради заявки.
- Кнопки «Принять» и «Отклонить» (причина по желанию, из готовых вариантов). Если мест нет, принять нельзя.
- Заявки старше 14 дней автоматически получают статус «истекла». Человек может отозвать свою заявку.
- Обе стороны получают уведомление (если включено в настройках).

## 7. Пустые состояния

| Где | Что показываем |
|---|---|
| Каталог — кругов нет | «Пока здесь тихо» + «Соберите первый круг» |
| Каталог — по фильтру ничего | «Ничего не нашли по „…“» + «Сбросить фильтры» / «Собрать такой круг» |
| Мои круги | «Вы пока ни в одном круге» + «Найти круг» / «Собрать свой» |
| Мои заявки | «Заявок нет» (без действия) |
| Профиль — пусто | Подсказка, что можно заполнить, и напоминание: «Всё закрыто, пока вы сами не откроете» |
| Уведомления | «Тихо — и это нормально. Мы пишем только о важном» + ссылка на настройки |
| Шаги в круге | «На этой неделе шагов ещё нет. Будьте первым» + кнопка «Написать шаг» |
| Заявки (создатель) | «Новых заявок нет» |
| Заблокированные | «Вы никого не блокировали» |
| Модерация | «Очередь пуста» |

Плюс состояния ошибок («Не получилось загрузить. Повторить») и загрузки (заглушки-скелеты).

## 8. Контраст и маленькие экраны

Проверено по WCAG 2.1 (норма для обычного текста — 4,5 : 1):

| Текст / фон | Контраст | Итог |
|---|---|---|
| Основной текст `#17201C` на фоне `#EDE5D7` | 13,3 | ✅ |
| Вторичный `#4A544F` на фоне | 6,3 | ✅ |
| Подсказки `#6B6559` на фоне / на карточке | 4,6 / 5,3 | ✅ (было 2,5 — исправлено) |
| Лесной `#1E5C4A` на фоне | 6,3 | ✅ |
| Белый текст на лесной кнопке | 7,8 | ✅ |
| Красный `#B23A26` на фоне / белый на красном | 4,8 / 6,0 | ✅ (было 3,9 — исправлено) |
| Белый на коралловом | 2,9 | ❌ → на коралловом только тёмный текст (5,8) |

- Коралловый, жёлтый и сиреневый — только для фона и украшений, не для мелкого текста.
- Карточки почти не отличаются от фона по яркости (1,15), поэтому у них **обводка + мягкая тень**,
  а секции различаются светлыми полосами и цветными плашками.
- Минимальная ширина — 320 px, без горизонтальной прокрутки (проверяется автотестом), зоны нажатия от 44 px,
  видимая рамка фокуса для клавиатуры, размер текста от 12 px только для второстепенных подписей.
