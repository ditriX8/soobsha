# Сообща — правила проекта для Claude

## О проекте
«Сообща» — веб-приложение, где люди собираются в маленькие группы («круги», 3–8 человек)
вокруг одной цели со сроком: выучить что-то, подготовиться к экзамену, сделать локальную инициативу.
Главный принцип: польза и результат, а не время в приложении.

Владелец проекта — начинающий разработчик. Объясняй решения простым языком, на русском.

## Стек
- Next.js (App Router) + TypeScript + Tailwind CSS
- Supabase (база данных, авторизация, хранение файлов) — подключается, когда понадобится
- Vercel — хостинг (публикация только с согласия владельца)
- Playwright — сквозные (e2e) тесты, папка `tests/e2e`
- GitHub Actions — автопроверки при каждом push и pull request

## Команды
- `npm run dev` — запуск локально
- `npm run lint` — проверка стиля кода
- `npm run typecheck` — проверка типов TypeScript
- `npm run build` — сборка
- `npm run test:e2e` — тесты Playwright (нужен запущенный локальный Supabase)
- `npm run test:db` — проверки прав доступа (RLS) и синхронизации на локальном Supabase
- `npx supabase start` — локальный Supabase (в облачной среде Claude: сначала `dockerd &`, затем `SUPABASE_INTERNAL_IMAGE_REGISTRY=docker.io npx supabase start`)
- `npx supabase db reset` — пересоздать локальную базу из миграций

Перед каждым коммитом: `npm run lint && npm run typecheck && npm run build && npm run test:db && npm run test:e2e`.

## Что можно делать самостоятельно
- Писать и менять код, тесты, документацию внутри этого репозитория.
- Делать коммиты и **отправлять (push) их в репозиторий `ditriX8/soobsha`** — на это есть постоянное разрешение владельца.
- Устанавливать бесплатные npm-пакеты, если они действительно нужны.
- Исправлять найденные ошибки и уязвимости.

## Что требует явного согласия владельца
- Выбор или смена концепции продукта.
- Любые платные сервисы и действия с финансовыми последствиями.
- Публикация приложения (production-деплой, открытие доступа публике).
- Удаление данных (таблиц, пользователей, файлов в хранилище, веток с чужой работой).
- Создание новых внешних ресурсов: проектов Supabase/Vercel, доменов, ключей API.
- Force-push и переписывание истории основной ветки.

## Правила честности
- Не имитировать работающие функции. Если что-то не реализовано — так и сказать.
- Не выдумывать статистику и не заявлять об уникальности без проверки.
- Если тест упал или шаг пропущен — сообщить об этом.

## Безопасность и приватность (обязательно)
- Не собирать точные адреса, телефоны, дату рождения и другую ненужную личную информацию.
  Город — только по желанию пользователя.
- Приватность по умолчанию максимальная: каждое поле профиля (кроме никнейма) — «Только я», пока пользователь сам не откроет.
- Жалоба не удаляет контент автоматически: скрывает только у автора жалобы; общее скрытие «на проверке» — по правилам из docs/tech-plan.md, решение — за модератором.
- Все таблицы в Supabase — с включённым RLS (Row Level Security) и политиками доступа.
- Секреты (ключи, пароли) — только в переменных окружения, никогда в коде и коммитах.
- Блокировка пользователей и жалобы — обязательная часть MVP.
- Защита от спама: ограничение частоты действий (rate limiting), проверка вводимых данных.

## Этичный дизайн
- Без бесконечной ленты, без искусственных «серий» и давления через уведомления.
- Достижения — за результат (завершённый круг, помощь другому), а не за время в приложении.
- Уведомления — по умолчанию минимальные, настраиваемые.

## Документы
- Концепция: docs/concept.md · Технический план: docs/tech-plan.md · Дизайн: docs/design/README.md
- Концепция v2 (совместный планер) и план многопользовательской работы: docs/planner-v2.md
- Приложение: src/planner (клиентское SPA с навигацией по якорям, данные — Supabase, синхронизация — Realtime)

- Цвета и шрифты — токены в src/app/globals.css. Мелкий текст не красить коралловым/жёлтым/сиреневым.

## Стиль кода
- TypeScript strict, понятные имена, маленькие компоненты.
- Тексты интерфейса — на русском.
- Мобильная версия обязательна для каждой страницы.
- Доступность: семантичная разметка, подписи у полей, контраст.
